# ach-agent 0.2.1 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship sandbox pods named after their Agent (`ach-agent--k8s-doctor-9f0456d5`), opencode autoupdate disabled in the sandbox, and the OpenShell workspace `ach-agent`, then remove any sandbox left behind in the `default` workspace.

**Architecture:** Two code commits already on branch `fix/runtime-pending` (`cdd3ca9` autoupdate, `624774a` sandbox names, which also finds and removes sandboxes still carrying the old `ws-<16 hex>` name). The workspace switch is configuration only: the chart value `openshell.workspace`, set by the e2e cluster script and by GitOps. The operator lists, checks and deletes sandboxes only in its configured workspace, so sandboxes still running in `default` at the switch become orphans and are deleted by hand once.

**Tech Stack:** Go operator, Python runtime, Helm chart, kind e2e, Flux GitOps, EKS read access through the aws-eks MCP.
